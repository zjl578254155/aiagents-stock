# 持仓逻辑评估 — 分析工作流 SOP

> 本文是 EOD 持仓评估模块「去 DeepSeek 化」后的标准分析流程。EOD 模块（services/eod_analysis_service.py）只负责**采集数据**，四档决策（HOLD/TRIM/WATCH/EXIT）由 **Claude 会话结合数据 + 联网新闻/政策归因 + v5 框架**做出并写回数据库。

## 一、定位

- 程序侧：不内嵌任何 LLM 自动判断。只做数据采集 + 调度刷缓存。
- 分析侧：由 Claude 在会话中完成判断，结论写回 `eod_analysis_records` 表，Streamlit UI 照常展示。
- 触发：用户说"分析持仓 / 按设计方案分析 XX"等，走下面标准闭环。

## 二、标准闭环（5 步）

1. **采集快照**
   `export_snapshots()` → 生成 `data/eod_snapshots/snapshot_<ts>.json`（全部启用观察股票，每只含买入逻辑 + 技术面 + 三口径基本面 + 新闻字段）。单只用 `build_snapshot(code)` 或 `export_snapshots(['代码'])`。

2. **联网归因（关键步骤，不可省）**
   对每只持仓**联网检索国内财经源**，分析近期股价走势的真实驱动。检索用 WebSearch 并以 `allowed_domains` 锁定国内站：`eastmoney.com, cninfo.com.cn, stcn.com, cs.com.cn, cnstock.com, sina.com.cn, 10jqka.com.cn, jrj.com.cn`；必要时 WebFetch 抓具体公告/新闻页。

   **2a. 强制红线证伪检索（最高优先级，每只必做，不得跳过）**
   先于"找催化"之前，**每只股票独立检索以下五类红线**，命中即写入结论并据此压低评级/置信：
   - **高管异动/落马**：董事长/总经理/财务总监 被查、留置、免去、解任、辞职、协助调查
   - **监管/违法**：立案、处罚、问询函/关注函、证监会、交易所监管措施
   - **财报诚信**：差错更正、追溯调减、业绩变脸、延期披露、审计非标/保留意见/无法表示意见
   - **造假/索赔质疑**：媒体或律师对财报真实性的公开质疑、投资者索赔
   - **退市/资金链**：退市风险、质押爆仓、债务违约、大股东大额减持
   > 教训（2026-06-08 五粮液）：当时 prompt 预埋了"ROE骤降但Q1回升+回购托底"的多头框架，agent 只去证实、未做红线证伪，**漏掉了"连续两任董事长被查 + 303亿营收追溯调减"这一颠覆性事实**，险些把它当加仓首选。红线证伪是为防这类"静默漏报"而设，**必须独立于催化检索单独执行**。

   **2b. 催化与归因**（红线扫清后再做）
   - **个股催化/事件**：参股、重组、订单、定点、减持、回购、业绩预告、异常波动公告等
   - **行业/国家政策**：如光伏"反内卷"限产、白酒消费税、军工航发订单与十五五、汽车以旧换新/反价格战/欧盟关税、半导体国产替代等
   - **近期行情归因**：解释为何涨/跌，判定当前价是【基本面驱动】还是【事件/情绪/概念驱动】

   **2b'. 影子股/题材归属强制自检（每只必答，与 2a 红线同级，不得跳过）**
   在"找催化"里，**参股/影子股/题材归属**须做成 per-holding 强制项，不能只当催化清单里的一个词：
   - 每只 agent 必须**显式回答**"该股是否为某公司/某热点主线的影子股或参股方、穿透持股比例几何、被参股方是否临近 IPO/重大事件"，**即使为'无'也要列出已检索**（防"没说=没查"静默漏报）。
   - **"个股放量大涨却查无当日 catalyst" = 影子股/题材炒作红旗，禁止当终点**；必须追问"是什么题材/影子股/资金主线在炒"，直到定位或明确标注"已穷尽检索仍未定位"。
   - 分析前先做一次"**当下最热主线（机器人/宇树、算力、固态电池等）↔ 全部持仓**"主动扫描，并 SELECT `eod_watch_stocks.thesis` 过一遍已固化的 `题材锚:` 行。
   > 教训（2026-07-03 金发×宇树）：金发+5%放量，agent 回"无 catalyst"被当成答案，漏掉"金发是宇树影子股(穿透持0.32-0.42%)、宇树7/2注册获批挂牌在即"这一常识级公开信息；合百×长鑫因既有标签查了、金发×宇树因无标签漏了。本项即为破"依赖既有标签被动匹配"的结构缺陷而设。

   **2c. 派 agent 的纪律（防确认偏误）**
   - 股票多时可派 3 个并行 general-purpose agent 各查 3 只，prompt 务必写明"立即执行、不要只输出计划"，否则可能停在计划态。
   - **prompt 里只给中性事实（代码、现价、仓位），严禁预埋"逻辑完整/护城河完整/拐点回升"等多头或空头结论**——预埋什么，agent 就只证实什么。让 agent 自己跑完 2a 红线证伪 + 2b 催化归因后再下驱动类型判定。
   - 每只 agent 都必须显式回答"2a 五类红线是否有命中"，**即使为'无'也要逐类列出已检索**，避免"没说=没查"的静默漏报。

   **2d. 每只必答核查输出模板（反软归因四闸，与 2a 同级：留空即视为未做，禁止静默跳过）**
   > 立意：散文规则会被时间压力跳过（教训：2b 早已列"参股"，2026-07-03 金发×宇树仍漏）。故把检查做成"跳过就露馅"的固定产出 schema，每只 agent 与主会话汇总都按此逐项回答：
   ```
   [代码 名称] 驱动类型:[基本面/题材/事件/混合]
     催化(含影子股/参股/题材归属,"无"须写"已查:无"):
     软归因量级校验(若归因为"技术性/机械性/情绪性/资金驱动"——该因素量级能否解释观察到的涨跌幅?算不平就写"驱动未定位",禁止当结论):
     红线对账(逐条 vs 底账 main_risk 历史红线:仍在/已解除/新增,不得让前轮红线静默蒸发):
     时点数值源(销量/涨跌幅/进度等精确数值:注明一手源[交易所/公司公告/行情接口]或"web线索待核";web 时点数值有跨日串扰风险,不得直接采信):
   ```
   四闸对应四类历史坑：软归因量级闸→obs#6247(科博达机械除权归因被推翻)；红线对账闸→obs#5868(五粮液跨轮红线丢失)；催化含影子股→金发×宇树漏查；时点数值源→obs#6524(搜索引擎串日期)。

3. **v6 四档重判**
   结合快照数据 + 联网归因，按 docs/持仓逻辑评估模块设计方案.md（v6）判四档：
   - **HOLD** 逻辑完整、估值合理 | **TRIM** 逻辑完整但估值偏高 | **WATCH** 逻辑存疑待确认 | **EXIT** 买入逻辑根本破坏
   - **四档映射统一口径（v6 第五节表格）**：进入预设减仓带 ≠ 升档（计划内仓位纪律维持原档+落 plans）；禁止评级横跳（教训：7/29-30 隆基 WATCH→EXIT→WATCH）。
   - **WATCH 强制出口（v6）**：进入/维持 WATCH 的 reasoning 必须含 `↑升回HOLD条件：…`／`↓降为EXIT条件：…` 两行，留空视为未完成；连续 4 周未触发 → 月复盘强制二选一。
   - **口径纪律（重要）**：长期水平/门槛看年报序列(12-31)；季报为 YTD 累计口径，仅用于看同比动能，**不得用单季 YTD 数字对照年度门槛（如 ROE≥15%）触发 EXIT**（这些口径已固化在快照的 `roe_trend / annual_roe_series / yoy_*` 字段）。
   - **双框架分尺（v6 五″节）**：【基本面驱动】走价值框架全套；【事件/题材驱动】改用"事件日历+兑现纪律+见顶信号"评估（此类票允许用量价/龙虎榜，估值语言不适用），不再只是"点明给选择权"。

4. **写回 DB**
   一律走 `scripts/save_decisions.py`（会话生成 JSON → 脚本幂等落库 → 逐条回读校验），禁止会话内联写库（教训：2026-07-27/07-31 共四次写库因输出中断丢失）。decision = `{action_code, action, confidence, margin_of_safety, thesis_still_valid, reasoning}`。reasoning 里带上【驱动类型】+ 催化/政策归因要点。
   **写库前必须先 SELECT 同日/近日已有记录**——可能存在另一会话已补写（教训：2026-07-29/30 两批并行会话记录与本会话评级横跳，隆基 WATCH→EXIT→WATCH）。评级与最近一条不同时，reasoning 首行注明「改评：原X→现Y，理由」，禁止无声改评。
   **条件动作必须结构化落 `eod_action_plans`**（`scripts/portfolio_ledger.py plan add`），禁止只写在 reasoning/日志文本里——"减1500@≥15.30"这类买卖点散在自由文本里永远统计不出命中率（2026-07-31 复盘结论）。用户报成交时走 `portfolio_ledger.py trade add`（自动记流水+更新台账+关闭对应计划）。

5. **组合层面汇总 + 约束检查（v6 强制）**
   有持仓股数(quantity)时按金额加权给：集中度、盈亏结构、降仓优先级、加仓候选。
   **必须输出"组合约束检查表"**（v6 五′节）：C1 题材仓位合计 / C2 单票占比 / C3 风格簇合计 × 实际值 × 是否超限（上限值见待办决策表 D6-D8，未填前按现状值标注"上限待定"）。**超限项必须点名并给减仓候选顺序（先减评级最低者），不允许静默。**

## 三、诚实边界（必须遵守）

- 不接受推测性结论：结论须有快照数据 / 公告 / 政策原文支撑，带可查来源链接。
- **卖方目标价、盈利预测、渠道测算一律标注"未验证"**，不混进确定结论。
- 联网检索是美国节点，**当天最新消息可能有时滞**；需登录的站（同花顺/雪球部分页）可能抓不动。
- 精确财务数字（季报营收/净利/口径勾稽）以 cninfo.com.cn 一季报原文为准，存疑处标注。
- 不预测未来价格（v5 框架本意）。

## 四、关键函数与文件

- 采集/写回：services/eod_analysis_service.py — `build_snapshot` / `export_snapshots` / `save_decision` / `refresh_all_data`
- 数据层：db/eod_analysis_db.py（`eod_watch_stocks` 持仓+买入逻辑、`eod_analysis_records` 决策记录）
- 调度器：schedulers/eod_scheduler.py（每日 15:30 仅 `refresh_all_data` 刷缓存，不决策）
- UI：ui/eod_analysis_ui.py（按钮"刷新数据并导出快照"/"导出 {code} 快照"；展示读 DB）
- 框架：docs/持仓逻辑评估模块设计方案.md（v5 四档 + 评估维度）
